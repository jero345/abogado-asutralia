Resumen de Seguridad de la Plataforma

Cómo se protegen el sitio web, el panel de administración y los datos de los clientes.

La plataforma está construida sobre infraestructura cloud moderna y administrada (Vercel + Supabase), con controles de seguridad estándar de la industria: conexiones cifradas, reglas de acceso a nivel de base de datos y un panel de administración protegido con autenticación. Ningún dato de registrantes es legible públicamente, y las funciones administrativas están restringidas solo a personal autorizado.

1. Arquitectura en pocas palabras

Sitio web público

Aplicación React alojada en Vercel. Se sirve por HTTPS a través de una red global (CDN) con protección anti-DDoS integrada. No contiene secretos.

Datos y backend del admin

Supabase (PostgreSQL administrado, autenticación y almacenamiento de archivos) sobre infraestructura de AWS. Todo el contenido, los registros y los documentos viven aquí.

No hay un servidor propio que parchear o exponer: ambos proveedores son plataformas administradas y auditadas (SOC 2).

2. Panel de administración — control de acceso

  • El área de administración (/admin) está protegida con autenticación de Supabase. Un visitante sin sesión válida es redirigido automáticamente al inicio de sesión: las páginas del admin nunca se muestran sin un usuario autenticado.
  • Las sesiones usan tokens firmados y con expiración (JWT) emitidos y verificados por Supabase; no se pueden falsificar.
  • Solo pueden ingresar las personas a las que el bufete les crea una cuenta explícitamente. Las cuentas se pueden revocar en cualquier momento.
  • Las contraseñas nunca se guardan en texto plano: Supabase las almacena como hashes con salt (bcrypt).

3. Seguridad en la base de datos — Row Level Security (RLS)

Todas las tablas aplican Row Level Security: es la propia base de datos la que decide quién puede leer o escribir cada fila, no la aplicación. Las reglas vigentes:

DatosPúblico (visitantes del sitio)Personal autorizado (admin)
Casos / artículos publicadosSolo lectura (lo publicado)Lectura y escritura total
Registros de formulariosSolo enviar — no puede leer ningún registroLeer, gestionar, exportar
Documentos subidosSin acceso directoAcceso por enlaces firmados temporales
Contenido en borrador / programadoNo visibleVisible y editable

En la práctica: una persona del público puede enviar un formulario de registro, pero no puede ver ningún registro — ni siquiera el suyo — a través del sitio web. Solo el personal con sesión iniciada puede ver los datos de los registrantes.

4. Privacidad de datos y documentos

  • Los envíos de formularios se guardan en una tabla privada que el rol público nunca puede leer.
  • Los archivos subidos junto a un registro se guardan en un bucket de almacenamiento privado; el personal los abre mediante enlaces firmados temporales (no enlaces públicos).
  • Los datos sensibles del registrante (nombre, contacto, información financiera) solo se muestran dentro del panel de administración autenticado.

5. Cifrado

  • En tránsito: todo el tráfico — sitio web, panel y llamadas a la API — va cifrado con TLS/HTTPS.
  • En reposo: Supabase cifra la base de datos y los archivos almacenados en disco.

6. "¿Por qué hay una llave en el sitio web?" — y por qué es seguro

El sitio público lleva una llave pública (anon key) de Supabase. Esto es por diseño y es seguro: la llave por sí sola no otorga ningún privilegio — cada solicitud que hace se sigue verificando contra las reglas de Row Level Security anteriores. No puede hacer nada que un visitante normal no esté ya autorizado a hacer (por ejemplo, leer contenido publicado o enviar un formulario).

La llave poderosa (service-role key), que sí puede saltarse esas reglas, nunca está en el sitio web ni en el navegador. Solo se usa en herramientas seguras del lado del servidor y se mantiene en secreto.

7. Cumplimiento e infraestructura

Supabase

Certificado SOC 2 Type II e ISO 27001; compatible con GDPR; HIPAA disponible en planes elegibles. Alojado en Amazon Web Services (AWS).

Vercel

Certificado SOC 2 Type II; HTTPS automático, red global en el borde (edge) y mitigación de DDoS.

8. Disponibilidad y respaldos

  • Infraestructura administrada, con escalado automático y alta disponibilidad en ambos proveedores.
  • Supabase realiza respaldos automáticos de la base de datos; la recuperación a un punto en el tiempo (point-in-time recovery) está disponible en los planes de producción.

9. Buenas prácticas recomendadas (para mantenerlo robusto)

  • Usar contraseñas fuertes y únicas para cada cuenta de administrador, y activar autenticación de dos factores (MFA), que Supabase admite.
  • Otorgar cuentas de administrador solo al personal que realmente las necesite; quitar el acceso cuando alguien se va.
  • Mantener el proyecto de Supabase en un plan que incluya respaldos diarios / recuperación a un punto en el tiempo.
  • Revisar periódicamente la lista de usuarios administradores.

En resumen

Los datos de clientes y registrantes están protegidos por reglas de acceso aplicadas por la base de datos, conexiones cifradas y un panel de administración con autenticación, todo sobre plataformas administradas y auditadas (SOC 2). El público puede enviar información, pero nunca leerla de vuelta; solo el personal autorizado del bufete puede verla y gestionarla.
