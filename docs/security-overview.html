Platform Security Overview

How the website, the admin panel and client data are protected.

The platform is built on modern, managed cloud infrastructure (Vercel + Supabase) with industry-standard security controls: encrypted connections, database-level access rules, and an authenticated admin area. No registrant data is publicly readable, and administrative functions are restricted to authorised staff only.

1. Architecture at a glance

Public website

React application hosted on Vercel. Served over HTTPS through a global CDN with built-in DDoS protection. Contains no secrets.

Data & admin backend

Supabase (managed PostgreSQL, authentication and file storage) running on AWS infrastructure. All content, registrations and documents live here.

There is no self-managed server to patch or expose — both providers are SOC 2 audited managed platforms.

2. Admin panel — access control

  • The admin area (/admin) is gated by Supabase Authentication. A visitor with no valid session is automatically redirected to the login screen — admin pages never render without a logged-in user.
  • Sessions use signed, expiring tokens (JWT) issued and verified by Supabase; they cannot be forged.
  • Only people the firm explicitly creates accounts for can sign in. Accounts can be revoked at any time.
  • Passwords are never stored in plain text — Supabase stores them as salted hashes (bcrypt).

3. Database security — Row Level Security (RLS)

Every table enforces Row Level Security, meaning the database itself decides who can read or write each row — not the application. The rules in force:

DataThe public (website visitors)Authorised staff (admin)
Published cases / articlesRead only (published items)Full read & write
Registration submissionsSubmit only — cannot read any submissionRead, manage, export
Uploaded documentsNo direct accessAccess via short-lived signed links
Draft / scheduled contentNot visibleVisible & editable

In practice: a member of the public can send a registration form, but cannot see anyone's submissions — not even their own — through the website. Only signed-in staff can view registrant data.

4. Registrant data & document privacy

  • Form submissions are written to a private table that the public role can never read back.
  • Files uploaded with a registration are stored in a private storage bucket; staff open them through temporary, expiring signed URLs rather than public links.
  • Sensitive registrant details (name, contact, financial information) are only ever exposed inside the authenticated admin panel.

5. Encryption

  • In transit: all traffic — website, admin panel and API calls — is encrypted with TLS/HTTPS.
  • At rest: Supabase encrypts the database and stored files on disk.

6. "Why is there a key in the website?" — and why it's safe

The public site carries a Supabase anon (public) key. This is by design and safe: the key on its own grants no privileges — every request it makes is still checked against the Row Level Security rules above. It can do nothing that a normal website visitor isn't already allowed to do (e.g., read published content, submit a form).

The powerful service-role key — which can bypass those rules — is never present in the website or the browser. It is used only in secure, server-side tooling and is kept secret.

7. Compliance & infrastructure

Supabase

SOC 2 Type II and ISO 27001 certified; GDPR-ready; HIPAA available on eligible plans. Hosted on Amazon Web Services (AWS).

Vercel

SOC 2 Type II certified; automatic HTTPS, global edge network and DDoS mitigation.

8. Availability & backups

  • Managed, automatically-scaled infrastructure with high availability across both providers.
  • Supabase performs automated database backups; point-in-time recovery is available on production plans.

9. Recommended best practices (to keep it strong)

  • Use strong, unique passwords for every admin account, and enable multi-factor authentication (MFA), which Supabase supports.
  • Grant admin accounts only to staff who genuinely need them; remove access when someone leaves.
  • Keep the Supabase project on a plan that includes daily backups / point-in-time recovery.
  • Review the list of admin users periodically.

In summary

Client and registrant data is protected by database-enforced access rules, encrypted connections, and an authenticated admin area, all on SOC 2-audited managed platforms. The public can submit information but can never read it back; only authorised firm staff can view and manage it.
